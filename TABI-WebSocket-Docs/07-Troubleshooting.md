# トラブルシューティング

## 1. 接続できない

確認順序:

1. WebSocketサーバーのプロセスが起動しているか。
2. URL・ポート・パスが正しいか。
3. フロントの環境変数が反映されているか。
4. Viteを再起動したか。
5. HTTPSページから `ws://` へ接続していないか。
6. セキュリティグループやファイアウォールが許可しているか。
7. リバースプロキシがUpgradeヘッダーを転送しているか。
8. Origin制限で拒否されていないか。
9. 認証に失敗していないか。
10. Socket.IOと標準WebSocketの方式が一致しているか。

## 2. PCでは動くがスマートフォンでは動かない

よくある原因は `localhost` です。

スマートフォンでの `localhost` はスマートフォン自身を指します。PC上のサーバーへ接続するには、PCのLAN内IPまたは本番ドメインを使用します。

その他:

- PCとスマートフォンが別ネットワーク
- OSファイアウォール
- サーバーが `127.0.0.1` のみで待受
- 自己署名証明書
- モバイルブラウザのバックグラウンド制限

## 3. 同じ端末では更新されるが、別端末へ届かない

確認項目:

- 両端末が同じWebSocketサーバーへ接続しているか。
- 両端末が同じ `groupId` のルームへ参加しているか。
- サーバーが送信者だけへ返していないか。
- `socket.emit` とルーム配信を取り違えていないか。
- 別端末側にイベントリスナーが登録されているか。
- 認証・所属確認で片方が拒否されていないか。
- 本番で複数サーバーに分散し、Redis Adapter等がない状態ではないか。

## 4. イベントが2回以上実行される

主な原因:

- `useEffect` のクリーンアップ不足
- ページ遷移ごとに新規接続
- React Strict Modeで開発時の副作用が見えた
- 同じイベントリスナーを複数登録
- API成功時のローカル更新とWebSocket受信の二重反映
- 再接続時にルーム参加やリスナー登録を重ねている

対策:

- 接続管理を共通化
- `socket.off(event, handler)` を実行
- 関数参照を固定
- IDで重複排除
- 自分自身を含める配信か除外する配信かを統一

## 5. 接続直後は動くが、しばらくすると反映されない

考えられる原因:

- プロキシやロードバランサーのアイドルタイムアウト
- スマートフォンの画面ロック
- Wi-Fiとモバイル通信の切替
- サーバープロセス停止
- ping/pong、heartbeat不足
- 再接続後にルームへ再参加していない

対策:

- heartbeatを有効にする
- 再接続イベントを監視する
- 再接続時にルーム参加をやり直す
- APIから最新状態を再取得する
- サーバー・ALB・プロキシのタイムアウトを確認する

## 6. CORSエラーまたはOrigin拒否

WebSocketサーバー側で許可Originを確認します。

悪い例:

```text
本番でも全Originを無条件許可
```

推奨:

```text
https://正式なTABIドメイン
http://localhost:5173
```

開発と本番を環境変数で分けます。

## 7. 403 / 認証エラー

- Cookieを送信する設定が不足していないか。
- CookieのSameSite、Secure、Domainを確認する。
- JWTの期限が切れていないか。
- 接続時認証とイベント受信時認可を混同していないか。
- URLクエリへ秘密情報を入れてログに残していないか。
- セッションをWebSocketサーバー側で参照できるか。

## 8. DBには保存されるが画面が更新されない

- 保存成功後に通知処理が呼ばれているか。
- イベント名の文字列が一致しているか。
- `groupId` の型が数値/文字列で食い違っていないか。
- ルーム名の組み立てが一致しているか。
- フロントで受信後のstate更新に失敗していないか。
- 受信後のAPI再取得URLが正しいか。

## 9. 画面は更新されるが再読み込みすると消える

DB保存より先にローカルstateまたはWebSocket通知だけを反映している可能性があります。

必ず次の順序にします。

```text
DB保存成功 → WebSocket配信 → 表示更新
```

## 10. 調査時に保存する情報

- 発生日時
- 操作したユーザー
- 対象groupId
- 使用端末・ブラウザ
- 接続URL
- Consoleログ
- NetworkのWebSocket Frames
- WebSocketサーバーログ
- APIレスポンス
- DB保存結果
- 再現手順
