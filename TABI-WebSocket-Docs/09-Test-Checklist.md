# WebSocketテストチェックリスト

## 1. ローカル基本テスト

- [ ] WebSocketサーバーが起動する
- [ ] Reactから接続できる
- [ ] 接続成功ログを確認できる
- [ ] 切断ログを確認できる
- [ ] 再接続できる
- [ ] 不正なデータでサーバーが停止しない
- [ ] API保存成功後にイベントが配信される
- [ ] API保存失敗時に成功イベントが配信されない

## 2. 異なる端末・ブラウザ

- [ ] ChromeとEdgeで同じグループを開く
- [ ] PCとスマートフォンで同じグループを開く
- [ ] AndroidとiPhoneで確認する
- [ ] 一方の更新が他方へ届く
- [ ] 別グループの端末へは届かない
- [ ] 操作者本人の画面で二重追加されない
- [ ] ページ再読み込み後もDBデータが残る

## 3. ルーム・権限

- [ ] グループ所属者は参加できる
- [ ] 非所属者は参加できない
- [ ] 存在しないgroupIdを拒否する
- [ ] 文字列・負数・NULLなど不正なgroupIdを拒否する
- [ ] 一般ユーザーは管理者ルームへ参加できない
- [ ] ログアウト後の接続を無効化できる
- [ ] 権限変更後の接続を適切に扱える

## 4. 切断・再接続

- [ ] Wi-Fiを一時的にOFFにする
- [ ] Wi-Fiからモバイル通信へ切り替える
- [ ] スマートフォンを画面ロックする
- [ ] PWAをバックグラウンドへ移す
- [ ] WebSocketサーバーを一時停止する
- [ ] 再接続後にルームへ再参加する
- [ ] 切断中の変更をAPI再取得で復元する
- [ ] 再接続でリスナーが重複しない

## 5. セキュリティ

- [ ] HTTPS環境でWSS接続する
- [ ] 許可されていないOriginを拒否する
- [ ] トークン期限切れを拒否する
- [ ] userIdを偽装しても他人になれない
- [ ] groupIdを変更しても他グループを購読できない
- [ ] 管理者フラグをクライアントから偽装できない
- [ ] ログへ秘密情報を出さない
- [ ] 大きすぎるメッセージを制限する
- [ ] 高頻度イベントにレート制限を検討する

## 6. 本番

- [ ] WSSの証明書が有効
- [ ] リバースプロキシのUpgrade設定が有効
- [ ] プロセスが常駐している
- [ ] プロセス異常終了後に自動復旧する
- [ ] サーバー再起動後に自動起動する
- [ ] ログを確認できる
- [ ] 監視・アラートが設定されている
- [ ] セキュリティグループが必要最小限
- [ ] ALB等のタイムアウトを確認済み
- [ ] デプロイ後に別端末テストを実施

## 7. 負荷

- [ ] 同時接続数の想定を記録する
- [ ] 1ユーザーが複数タブを開いた場合を確認する
- [ ] 大量イベント時に画面が固まらない
- [ ] サーバーのCPU・メモリを確認する
- [ ] 切断済み接続が残り続けない
- [ ] 必要ならRedis等の導入条件を整理する
