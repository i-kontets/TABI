# 共通通知サービス

作成日: 2026-07-23

この資料は、通知履歴の作成、受信者登録、通知設定判定、FCM送信、`delivered_at` 更新をまとめて行う共通通知サービスの説明です。

## 対象ファイル

- `api/Notifications/Service/NotificationRepository.php`
- `api/Notifications/Service/NotificationSettingsResolver.php`
- `api/Notifications/Service/NotificationService.php`
- `api/Notifications/cli/test_notification_service.php`

## 目的

TABIでは、プッシュ通知が届かなかった場合でも、アプリ内の通知一覧から内容を確認できる必要があります。

そのため、共通通知サービスでは次の順序で処理します。

1. 入力値を検証する
2. 受信者ユーザーの存在を確認する
3. `notifications` に通知本体を登録する
4. `notification_recipients` に受信者ごとの履歴を登録する
5. DBトランザクションをcommitする
6. `notification_settings` を確認する
7. 通知ONかつ有効端末ありの場合だけFCM送信する
8. 1台以上成功した受信者だけ `delivered_at` を更新する

FCM送信中にDBトランザクションは保持しません。外部通信待ちの間にDBロックを伸ばさないためです。

## 通知履歴とプッシュ通知の違い

通知履歴はTABIアプリ内で確認できる情報です。プッシュ通知はOSやブラウザへ届く外部通知です。

通知設定がOFFの場合でも、通知履歴は作成します。プッシュ通知がOFFなだけで、TABI内の通知一覧から確認できる状態を保つためです。

## 通知設定

`notification_settings` のカテゴリ対応は次の通りです。

| notificationType | DBカラム |
|---|---|
| `chat` | `chat_notification_enabled` |
| `schedule` | `schedule_reminder_notification_enabled` |
| `survey` | `survey_deadline_notification_enabled` |
| `member` | `member_join_notification_enabled` |
| `split_bill` | `split_bill_notification_enabled` |
| `system` | 個別カラムなし。現時点では送信許可 |

設定レコードがまだ存在しないユーザーは、既存 `Settings.php` と同じく初期値ONとして扱います。

## delivered_at

`delivered_at` は、受信者のいずれか1台以上の端末へFCM送信できた場合だけ更新します。

更新条件:

```sql
UPDATE notification_recipients
SET delivered_at = COALESCE(delivered_at, NOW())
WHERE recipient_id = :recipient_id
  AND user_id = :user_id
  AND delivered_at IS NULL;
```

`recipient_id` と `user_id` の両方を条件に入れます。他ユーザーの通知履歴を誤更新しないためです。

## CLI

CLI確認用スクリプト:

```bash
php api/Notifications/cli/test_notification_service.php --help
```

### dry-run

DB INSERT、FCM送信、`delivered_at` 更新は行いません。

```bash
php api/Notifications/cli/test_notification_service.php --user-id=<USER_ID> --dry-run
```

### create-only

`notifications` と `notification_recipients` へ登録します。FCM送信は行いません。

```bash
php api/Notifications/cli/test_notification_service.php --user-id=<USER_ID> --create-only
```

Codexはこのコマンドを実行しません。DBへINSERTするためです。

### send

通知履歴を作成し、通知設定ONかつ有効端末ありの受信者へFCM送信します。

```bash
FCM_SEND_ENABLED=true php api/Notifications/cli/test_notification_service.php --user-id=<USER_ID> --send
```

Codexはこのコマンドを実行しません。DB INSERT、FCM実送信、`delivered_at` 更新を伴うためです。

## CLIテスト通知

CLIでは次のテスト通知を使います。

- `notificationType`: `system`
- `notificationSubtype`: `notification_service_test`
- `targetType`: `system_notice`
- `actionPath`: `/TABI/notifications`
- `detailData.source`: `notification_service_cli_test`

## テストデータ削除SQL

手動で `--create-only` または `--send` を実行した後、テストデータを削除する場合の確認SQLです。

```sql
SELECT notification_id, notification_type, notification_subtype, target_type, created_at
FROM notifications
WHERE notification_subtype = 'notification_service_test'
  AND JSON_UNQUOTE(JSON_EXTRACT(detail_data, '$.source')) = 'notification_service_cli_test'
ORDER BY notification_id DESC;
```

削除SQLです。`notification_recipients` は外部キー `ON DELETE CASCADE` により、`notifications` の削除に連動して削除されます。

```sql
DELETE FROM notifications
WHERE notification_subtype = 'notification_service_test'
  AND JSON_UNQUOTE(JSON_EXTRACT(detail_data, '$.source')) = 'notification_service_cli_test';
```

Codexは削除SQLを実行しません。実行前に対象件数を必ず確認してください。

## セキュリティ

戻り値、ログ、Markdownへ次の実値を含めないでください。

- `push_token`
- `token_hash`
- OAuthアクセストークン
- Authorizationヘッダー
- `private_key`
- `client_email` の実値
- DB認証情報
- メールアドレス
- サービスアカウントJSONの実ファイル名

FCM dataには文字列だけを入れます。`detailData` 全体はFCM dataへ入れません。
