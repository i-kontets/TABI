# TABI 通知機能 進捗調査結果

作成日: 2026-09-14

## 1. 総合進捗

**通知機能全体：48%**

理由:

- Firebase初期化、通知許可、FCMトークン取得、端末登録API、通知設定API、通知履歴API、未読件数API、既読API、FCM HTTP v1送信部品は実装済み。
- ただし、通常の業務イベント（チャット、アンケート、予定、メンバー参加、割り勘など）から共通通知サービスを呼ぶ接続が確認できない。
- `Service Worker` は Firebase Messaging 初期化までで、`onBackgroundMessage`、`showNotification()`、`notificationclick` が未実装。
- フォアグラウンド受信の `onMessage()`、Toast、通知一覧即時更新は未実装。
- `NotificationListPage` / `NotificationDetailPage` は存在し import もされているが、`App.jsx` の `<Routes>` に `/notifications` / `/notifications/:notificationId` が登録されていないため、現状ベルクリックから通知一覧を表示できない。
- ログアウト時のFCMトークン削除、端末無効化、ユーザー切り替え対策は未実装。

## 3. 完成している処理

- Firebase SDK導入: `package.json` に `firebase` あり。
- Firebase初期化: `src/firebase/firebaseConfig.js` が `VITE_FIREBASE_*` を読み取り、不足時はエラー。
- Messaging対応確認: `src/firebase/firebaseMessaging.js` が `isSupported()` を使う。
- 通知許可画面: `NotificationPermissionPage` がボタン押下時のみ `requestFirebasePushToken()` を呼ぶ。
- FCMトークン取得: `src/firebase/firebasePushToken.js` が `Notification.requestPermission()`、SW登録、`getToken()` を順に実行。
- 端末登録API: `api/Notifications/RegisterDevice.php` が `user_devices` に保存。
- 通知設定取得/保存: `api/Notifications/Settings.php` と `NotificationSettingsPage` が接続済み。
- 通知履歴API: `List.php`、`UnreadCount.php`、`MarkRead.php`、`MarkAllRead.php` が実装済み。
- FCM HTTP v1送信部品: `FcmConfig`、`FcmAccessTokenProvider`、`FcmHttpClient`、`FcmSendService` が存在。
- 無効トークン無効化部品: `FcmSendService` が `invalidToken` 時に `FcmDeviceRepository::deactivateDevice()` を呼ぶ。

## 4. 一部実装

- 通知一覧画面: `src/pages/Notifications/NotificationListPage.jsx` はAPI連携済みだが、`App.jsx`にルートがない。
- 通知詳細画面: `NotificationDetailPage.jsx` は `location.state` 前提。URL直打ちやリロード時のDB再取得なし。
- 通知クリック: アプリ内通知一覧からのクリックは既読化して遷移するが、OS通知クリックは未実装。
- FCM送信: CLI/共通サービスとしては作られているが、チャット送信などの本処理から呼ばれていない。
- 通知設定反映: `NotificationSettingsResolver` は実装済みだが、通常イベント経由で使われていない。
- 複数端末: DB構造は対応。ただし同じFCM tokenが別ユーザーで登録されると `ON DUPLICATE KEY UPDATE user_id = VALUES(user_id)` により所有ユーザーが移る。

## 9. 現在の実処理フロー

### 通知許可

```text
ユーザーが /mypage/notification-permission のボタンを押す
↓
NotificationPermissionPage.requestPermission()
↓
requestFirebasePushToken()
↓
Notification API / Service Worker / secure context を確認
↓
Notification.permission が default なら requestPermission()
↓
registerFirebaseServiceWorker()
↓
getFirebaseMessaging()
↓
getToken()
```

ページ表示直後に勝手に許可要求する処理は確認されない。

### token登録

```text
getToken()成功
↓
registerNotificationDevice()
↓
POST /TABI/api/Notifications/RegisterDevice.php
↓
セッション user_id を取得
↓
token検証、token_hash生成
↓
user_devices に INSERT / ON DUPLICATE KEY UPDATE
```

### 通知作成

```text
CLI または将来の業務処理
↓
NotificationService.createAndSendNotification()
↓
入力検証
↓
通知設定確認
↓
notifications / notification_recipients 作成
```

現状、チャットや割り勘などの通常APIからこの流れへの接続は未確認。実運用イベントでは未実装扱い。

### FCM送信

```text
NotificationService mode=send
↓
FcmSendService.sendToUser()
↓
有効な user_devices を取得
↓
OAuth2アクセストークン取得
↓
FCM HTTP v1 APIへPOST
↓
成功なら sent、無効tokenなら user_devices を無効化
```

通常イベントから未接続のため、アプリ全体としては一部実装。

### Foreground受信

未実装。`onMessage()` の検索結果なし。

### Background受信

`firebase-messaging-sw.js` は `getMessaging(firebaseWorkerApp)` まで。`onBackgroundMessage()` と `showNotification()` は未実装。

### 通知クリック
